**Производительность**

1. **Видео — основной измеренный источник лишнего трафика.** `components/HeroMedia.jsx:30` включает два `<video preload="auto">`, затем перебирает четыре исходных ролика. За примерно 20 секунд локальный браузер передал около 12,8 MB, из них 12,15 MB приходится на четыре mp4. После прокрутки на 2000 px активный ролик продолжал играть. Эта же карусель используется на страницах разделов через `PageHero`.
   Предложение: на телефоне использовать постер; для десктопа сделать отдельный короткий сжатый фон, останавливать видео и таймеры вне экрана и при скрытой вкладке. Ограничение `saveData` и `prefers-reduced-motion` уже есть — его следует сохранить.

2. **Исходники изображений крупные, но это не равно их сетевому весу.** Фото PNG весят примерно 1,6–2,1 MB, однако большая часть выводится через `next/image`. Не стоит объявлять их главным тормозом без замера оптимизированных ответов. Отдельно полезно подготовить лёгкую горизонтальную картинку для социальных превью: сейчас используется исходный вертикальный `/img/doctor.png`.

3. **В `public` есть неиспользуемые исходники.** В частности, `public/inst/dr.markaryan_ed/` описана в коде как сырая выгрузка. Отсутствие ссылок не закрывает доступ по прямому URL. Стоит вынести действительно неиспользуемые материалы из публичной раздачи после проверки зависимостей. Это уменьшит объём публикации; само по себе не ускорит страницу, которая их не запрашивает.

**Адаптивность и доступность**

- **Шапка меняет цвет по неверному ориентиру.** `components/Header.jsx:39` ориентируется на `0.82 × window.innerHeight`, а не на низ hero. На телефоне после прокрутки `/gemorroy` на 450 px низ hero уже выше низа шапки, но шапка остаётся `is-light`. Светлые ссылки оказываются на светлом фоне. На высокой главной происходит обратное: переключение может начаться раньше конца hero. Лучше наблюдать границу самого блока.
- **Cookie-баннер частично перекрывает плавающую запись.** На 390×844 видимый низ FAB заходит под баннер примерно на 20 px. `components/CookieConsent.jsx:20` использует `contentRect.height`, где нет padding и border. Измерять полную высоту и учитывать нижний отступ баннера.
- **Нет удержания и восстановления фокуса в записи.** После пяти Tab фокус выходит из диалога на страницу; после Escape из исходного положения возвращается на `body`. В `BookingModal` есть начальный focus, но нет полного управления диалогом. Применить нативный `<dialog>` либо корректно реализовать удержание/возврат фокуса и неактивный фон.
- **У видеопросмотра такая же проблема.** `components/Reels.jsx` не задаёт семантику диалога и не переносит фокус: он остаётся на закрытой фоном карточке. Имеет смысл общий компонент диалога для видео и записи.
- **Мобильное меню остаётся открытым после Escape.** В `Header` нет обработчика, ограничения высоты и внутренней прокрутки. На 390×844 меню занимает около 548 px по высоте; следует отдельно обеспечить работу на низких экранах и в горизонтальном положении.
- **Узкие экраны обрезают содержимое.** На 320 px блок контактов расширяет документ до 342 px; `/license` — до 355 px; `/privacy` — до 409 px. Заголовок политики обрезается даже на 390 px. Нужны переносы длинных слов, `min-width:0` для нужных grid/flex-элементов и адаптация кнопок/отступов. `overflow-x:hidden` маскирует проблему.
- **Внутренняя навигация колоноскопии заходит под шапку.** `styles/service.css:293` задаёт `top:60px`, хотя фактическая шапка на 390 px имеет высоту около 85 px. Использовать единую высоту и учитывать оба закреплённых ряда при переходах к якорям.
- **Reduced motion реализован не до конца.** Анимации выключаются, но `scroll-behavior:smooth` остаётся; `.reveal {opacity:1}` проигрывает по специфичности `.reveal-ready .reveal`. Лучше обеспечить видимость без эффекта появления и отключить плавную прокрутку для этого режима.

**Аналитика и метаданные**

- **Повторный `init` Метрики при медленной загрузке.** `lib/metrika.js:91` считает запуск завершённым только после события счётчика. Каждый `reachGoal` до этого снова вызывает `initMetrika`. С заглушкой внешнего скрипта два открытия записи дают очередь `init, init, init`. Нужен отдельный флаг постановки инициализации в очередь; готовность счётчика и факт запроса инициализации — разные состояния.
- **Семь страниц разделов лишились `og:image`.** Это подтверждено по итоговому HTML. `lib/sections.js:116` задаёт собственный `openGraph` без `images`, заменяя родительский объект. У этих страниц также остаются Twitter title/description главной; это касается и служебных страниц. Вынести общую фабрику метаданных с явным формированием всех полей.
- **Выбор cookie неудобно менять.** Сейчас политика предлагает очистить данные сайта в браузере. Полезна ссылка «Настройки cookie» в подвале с возможностью пересмотреть выбор. При реализации отказа после принятия потребуется остановка обоих счётчиков, а не только скрытие баннера.
- **Не различается контекст обращения.** «Запросить памятку», «Уточнить стоимость», «Записаться» открывают одинаковый диалог и отправляют одну цель. Передавать цель действия/страницу в состояние диалога и обезличенную аналитику, чтобы было понятно, какая часть сайта помогает обратиться. Клик по мессенджеру при этом не считать подтверждённой записью.
- **Старый адрес внутри нового сайта.** В `components/DoctorCard.jsx:52` ссылка «Подробнее о враче» ведёт на `/#about`, затем клиентский редирект переводит на `/o-vrache`. Сразу использовать новый адрес: это уберёт промежуточную загрузку главной и её медиа.
- **В sitemap дата меняется при каждой сборке.** `app/sitemap.js` ставит всем страницам `new Date()`. Лучше хранить реальную дату обновления содержимого или не задавать `lastModified`, если таких данных нет.

Для SPA-просмотров Яндекс документирует метод [`hit`](https://yandex.ru/support/metrica/ru/objects/hit). Замена вложенных объектов metadata описана в [документации Next.js 15](https://nextjs.org/docs/15/app/api-reference/functions/generate-metadata#merging).

**Уточнения по зависимостям и документам**

Next.js 15.5.19 попадает в диапазоны опубликованных advisories. Например, [GHSA-2xp9-vwfh-vxw4](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4) касается обработки AVIF в Image Optimization API и указывает исправление в 15.5.24. Другие предупреждения относятся к Windows, Server Actions, rewrites или обработке недоверенных данных. В просмотренном коде нет загрузки пользовательских файлов, Server Actions и удалённых image patterns; конфигурация production полностью неизвестна. Поэтому вывод — обновить зависимости и проверить применимость, а не утверждать наличие доступного извне RCE.

Из кода нельзя установить фактический состав лицензии: нужна актуальная выписка и сверка опубликованных данных владельцем. Настоящий обзор не подтверждает и не опровергает право клиники оказывать эти услуги.
